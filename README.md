# 汉画像·百戏乐舞 V5 Full Keyframes

离线全屏互动装置网页。实体摄像头使用本地人像分割模型，模拟摄像头使用可控前景，把人体轮廓映射到画面中 63 个实际建筑画格；触发状态驱动画面中的汉画像人物、乐队群像、局部矿物色特效和同步声部。

本版本号：`5.0.0-v5-full-keyframes`。32 组独立人物/群像来源均配有 3×3、九帧的真实动作姿势；构建器再将它们合成为 32 个单人、12 个双人、8 个三人和 8 个群像运行动作表。63 个画格全部使用关键帧：未触发显示第 1 帧灰像，触发后人物转黑，并按乐器演奏、舞蹈、行进或礼仪动作循环，不再使用整张人物图的网格扭曲。

## 1. 运行

要求：Node.js 18 或更高版本。运行作品本身不需要 Python，也不需要互联网。

```bash
npm start
```

浏览器打开：

```text
http://127.0.0.1:4173
```

实体摄像头必须从安装电脑本机的 `localhost` / `127.0.0.1` 地址打开；普通局域网 `http://192.168.x.x` 不属于浏览器安全上下文，只适合远程查看或触控，不能保证 `getUserMedia()` 可用。若必须在另一台设备调用摄像头，应部署 HTTPS。

也可以直接使用：

- macOS：双击 `start.command`
- Windows：双击 `start.bat`
- Linux：执行 `./start.sh`

健康检查：

```bash
curl http://127.0.0.1:4173/health
```

作品舞台始终使用浏览器完整 CSS 视口，不存在固定 16:9 播放框。为了保证 63 节点实时动画，内部 Canvas backing store 默认限制在约 120 万像素；4K 和超宽屏仍为完整全屏 CSS 输出，但不是原生 4K 像素缓冲。

## 2. 现场使用

进入作品后，右下角“控”打开操作面板。

### 鼠标模式

点击“鼠标模式”。鼠标按屏幕上的真实非均匀画格命中，点击哪个画格只触发该画格；多点触摸仍按手指附近的身体覆盖范围同时触发相邻区域。

右下角声音按钮显示“声”表示声音开启，显示“静”表示静音。重新开启声音时程序会主动恢复浏览器音频；“测试声音”可绕过人物触发播放独立测试音。控制面板的人物识别监视器同时显示音频状态、63 条独立实录音轨加载数和实时输出电平。

### 人脸模式

1. 点击“人脸模式”，浏览器会立即请求摄像头权限。
2. 允许访问后，离线 MediaPipe Selfie Segmenter 会在本机加载，无需离场采集空背景。
3. 人物识别监视器会叠加红色真实人像轮廓、黄色人物框和识别置信度；主画面同步显示浅灰黑色轮廓。只有人像像素参与触发，普通窗户、地图或光照变化不会因画面变化直接触发。
4. 确认“识别人物”“人物像素”和“触发格子”均变为非零，人物声部才会响起。
5. 打开“摄像头标定”，拖动四角，使触发平面对应真实楼梯、走廊或表演区域。
6. 保存标定预设，最后进入浏览器全屏。

摄像头轮廓按标定位置直接命中实际视觉画格，不再把规则 9×7 编号误当作非均匀画像节点。音量随覆盖比例变化，并按画面左右位置设置立体声声像。

## 3. 视觉结构

横屏场景与 9×7 触发平面已经解耦，不再把规则触发网格直接当作视觉构图。当前横屏结构包含：

- 63 个密集、非均匀画像石建筑画格；
- 左右连续纹样边框；
- 上下连续云气、神兽和几何纹样带；
- 8 条主要横梁 / 栏杆层；
- 5 个中央仪式舞台画格；
- 中央纵向建鼓、编钟、阶道和多层仪式空间；
- 狭窄画格使用放大的单人乐师，宽画格使用双人/三人组合，中央台阁使用大型群像；
- 灰色待机像、墨黑激活像，以及与演奏起音同步的金、朱、青、紫局部矿物色、墨迹和粒子效果。

竖屏使用独立构图，不是把横屏场景压缩成一条窄画面。

结构指标可从调试接口 `window.__HAN_TEST_API__.getState().sceneStructure` 读取。

## 4. 素材数量与事实口径

本项目当前精简为运行所需素材：

- 63 个视觉节点实际使用 47 个不同人物构图及对应的 47 套九帧动作表；
- 未被当前 63 格引用的构图、旧版动作、高清制作母版和生成中间文件均已移除；
- 每个构图仍只由一个确定建筑画格触发，运行时会按不透明轮廓裁掉透明留白；
- 63 个画格仍各自使用不同的 Opus 音轨。其中 36 格优先使用操作员提供的 30 秒“音色试听册”片段，覆盖编钟、古琴、古筝、南箫、埙、笙、管子、唢呐、琵琶、三弦、柳琴、扬琴、京胡、二胡、马头琴及多种民乐合奏；另外 27 格继续使用原有 VCSL CC0 实录循环补齐。
- 多声部共用传输时钟和左右舞台声像；混响与压缩只作轻量安全处理，尽量保留原录音的呼吸、击弦、敲击和房间尾音。

`assets/audio-auditions/` 是用户指定的本地试听运行副本，36 条正式映射已直接写入 `config/scene.json`。试听册自身说明其商业 Demo 仅供本机选音，因此对外发布或重新分发本项目之前，必须另行确认这 36 段声音的授权；另外 27 段 VCSL 音频仍为 CC0。

因此，本项目**不是 63 位分别独立绘制的人物**。设计来源与授权说明见 [`ASSET_NOTES.md`](ASSET_NOTES.md)。

参考视频仅用于研究空间构图和交互机制；交付包没有从参考视频中抠取、复制或重发原作者画面像素和音乐。

## 5. 摄像头状态与恢复

`CameraController` 的传输层状态为：

```text
idle → requesting → live
                 ↘ disconnected → reconnecting → live
                 ↘ error
```

`InputController` 在传输层之上增加背景分割管线状态：

```text
capturing-background
ready
```

断线恢复使用可取消的持续重连循环：临时 `NotReadableError`、`AbortError`、视频等待超时等会继续指数退避重试，延迟有上限但循环不会只尝试一次；永久权限拒绝、浏览器安全限制和不可满足约束会停止自动重试并提示人工处理。成功恢复后连续失败计数归零。

每次启动会带 generation token。快速执行“实体 → 模拟 → 实体”时，旧 `getUserMedia()` 即使稍后才返回，也只会停止自己的 tracks，不能覆盖新来源。视频超时、`play()` 失败、来源切换和手动停止都会停止已取得的 tracks 并清空 `video.srcObject`。

## 6. Homography 标定

标定使用真正的 3×3 projective homography，而不是四角双线性插值。系统维护：

- 摄像头平面 → 视觉舞台平面的单应矩阵；
- 视觉舞台平面 → 摄像头画面的逆矩阵；
- 四角重投影误差；
- 自交、极小面积、越界、非有限矩阵和奇异矩阵检查；
- 标定预设保存、导入和导出。

非法四边形会被拒绝，并保留上一次有效标定。

- macOS 与 Windows 目标机启动脚本；
- 仍需在目标机器完成长时间连续运行和真实音箱试听；
- 视觉与音乐发布前的最终版权和艺术史审查。
