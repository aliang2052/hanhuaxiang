- 真实楼梯 / 走廊、投影仪与四角 Homography；

- 视觉、音乐、生成素材许可与艺术史终审。

实体摄像头应从安装电脑的 `localhost` / `127.0.0.1` 打开；普通局域网 HTTP 地址不属于浏览器摄像头安全上下文。

## 6. 用户验收后的鼠标精准修正

用户在实际操作中发现，鼠标点击一个画格会同时选中多个其他画格。源码审查确认有两个原因：鼠标沿用了人体椭圆覆盖范围；非均匀视觉画格与均匀 9×7 摄像头触发平面已经解耦，但鼠标仍按后者命中。

现已改为：

- 鼠标直接对屏幕上的真实非均匀画格做命中测试；
- 重叠区域选择画面中最上层的画格；
- 点击一个画格时，仅该画格覆盖率为 100%；
- 切换输入模式时清除上一模式的激活残留；
- 多点触摸继续使用邻近身体面积覆盖；
- Homography 与模拟背景分割保持兼容；实体摄像头改走本地语义人物检测。

独立浏览器回归结果：鼠标测试点命中 ID `27`，`positiveCoverageCount = 1`、`activeIds = [27]`、`pointerTargetIds = [27]`。加入人像轮廓、实际画格映射与空间声音诊断后，完整 E2E 为 36 + 10 + 10 + 8 = 64 项全部通过，外部请求和页面/控制台错误为 0。

前述 60 分钟长稳发生在后续鼠标精准、人物识别监视器和声音诊断修正之前；这些后续改动已完成完整单元、服务和浏览器 E2E 回归，但没有把旧长稳伪装成修改后的重新执行结果。

## 7. 用户验收后的声音状态修正

用户启动实体摄像头后反馈无声。后续现场截图确认静音未勾选，但旧背景差分把窗户、地图和人脸拆成多个“前景”组件，既不是真正的人物识别，也不能形成可靠触发。浏览器诊断同时确认 AudioContext 为 `running`、9 / 9 音轨已加载；问题根因在识别输入而非音频文件。

已补强产品行为：

- 右下角按钮以“声 / 静”直接显示当前状态；
- 标题、无障碍名称和 `aria-pressed` 与声音状态同步；
- 从静音恢复时主动调用 Web Audio `resume()`；
- 仅当 AudioContext 确实进入 `running` 才报告恢复成功；
- 增加独立“测试声音”按钮，不依赖人物识别即可播放测试音；
- 增加实时音频输出电平，测试状态包含 `audio.contextState` 与 `audio.outputLevel`；
- 面板明确提示声音已开启、已关闭，或仍被浏览器暂停。
- 控制面板增加常驻人物识别监视器，实时显示摄像头、真实人像 Mask、人物框、识别置信度、人物像素、触发格数与音频链路；主画面同步投影浅灰黑人物轮廓；
- 实体摄像头改用本机 MediaPipe Selfie Segmenter 人像分割，不再使用检测框椭圆，也不要求离场采集空背景；模拟摄像头仍保留可重复验收的空场流程；
- 摄像头像素直接映射到非均匀视觉画格，修复规则 9×7 索引与视觉节点 60/63 错位；音量按真实覆盖率变化并按左右位置设置声像。

实体摄像头的人物框、人物像素和触发格子变为非零后，人物声部才会被触发；模拟摄像头仍须先完成“采集模拟空场”。物理扬声器最终是否可听仍需操作者点击“测试声音”现场确认；自动化只能验证浏览器内信号链路，不能替代人的听觉验收。
