# ChatGPT Pro 开发任务：汉画像互动乐队生产化升级

## 协作角色

- **ChatGPT Pro（外部高级工程师）**：深入研究参考视频，提出技术方案并编写完整代码。
- **Codex（总负责人）**：维护 Git 仓库，定义验收标准，审查 ChatGPT Pro 的结论和代码，运行测试、追问纠错并决定是否合格。

ChatGPT Pro 的说明、截图和自测报告都只是待验证材料，不能代替 Codex 的独立源码审查与运行验收。

## 当前基线

仓库保存了现有 v1.0.0 原型：离线浏览器应用、9×7 共 63 个触发格、自动/指针/摄像头三种输入、同步循环音频、空场背景差分、四角标定和本地 Node 服务器。

它可以运行，但还不是可交付的真实项目。已确认的主要缺陷：

1. 视觉只是统一 9×7 网格和 8 类重复人物，未复现参考视频的非均匀建筑式布局、中央舞台、多尺寸画格和丰富群像。
2. 主画面固定为 1920×1080，并使用 `object-fit: contain`；16:10、超宽屏和竖屏会出现明显黑边。
3. 摄像头使用 192×108 固定背景差分，缺少光照适应、连通区域过滤、断线重连和实体硬件验收。
4. 四角标定使用双线性插值，并非真正的 projective homography。
5. 在非 camera 模式直接点击“采集空场背景”时，采集状态不会推进。
6. 测试脚本硬编码 `/usr/bin/chromium`，无法在当前 macOS 环境直接复现。

## 第一阶段必须完成（P0）

### 1. 视觉与布局

- 重新研究当前对话中的参考视频，建立更接近参考作品的非均匀画格结构：上下装饰边框、左右纹样、中央舞台、大中小画格组合。
- 不再让 63 个格子仅重复 8 张素材。提供明显更丰富的独立人物/群像组合与可配置场景。
- 保持“浅灰待机 → 深黑激活 → 少量局部彩色晕染”的核心视觉语言。
- 激活动画需有可辨识动作差异，避免所有人物只做统一呼吸和摆动。
- 素材必须为本项目可合法使用的原创或明确授权资源；在 `ASSET_NOTES.md` 记录来源与许可。

### 2. 真正的全屏响应式舞台

- 主作品不能再表现为居中的 16:9 视频框。
- 支持至少 1920×1080、1920×1200、2560×1440、3840×2160、超宽屏和 390×844。
- 不得出现大面积黑边；允许按安全区裁切装饰背景，但核心触发画格和人物不能被裁掉。
- 指针/触摸坐标必须与响应式画面保持精确一致。
- 操作员 UI 与观众画面解耦；隐藏 UI 后只留下作品。

### 3. 摄像头与触发稳定性

- 修复任意模式下点击“采集空场背景”的流程；按钮应自动切换到 camera 模式或明确阻止并解释。
- 增加摄像头断线检测与自动重连。
- 加入光照缓变适应、连通区域/面积过滤、阴影与小噪点抑制。
- 人物短暂停留不能被背景模型吸收；多人同时进入时仍应稳定。
- 调试界面显示原始画面、前景 Mask、FPS、处理延迟、摄像头状态和每格覆盖率。
- 原始视频和 Mask 默认不保存、不上传。

### 4. 标定系统

- 使用真正的 3×3 homography 完成摄像头平面到触发平面的投影映射。
- 禁止四角交叉、自相交、面积过小或越界配置。
- 支持标定预设命名、保存、切换、导出和导入。
- 标定变化后立即重建映射，并提供可视化验证网格。

### 5. 生产运行与恢复

- 本地离线运行，不依赖 CDN、云接口或远程字体。
- 处理服务端口占用、静态文件错误、摄像头拒绝授权、音频解码失败和全屏失败。
- 提供健康检查、可读错误页和操作员可执行的一键恢复。
- macOS/Windows 启动脚本应检查 Node 版本、端口占用并给出明确提示。
- 保存配置时必须有 schema/version 校验，损坏配置应自动回退默认值。

## 工程质量要求

- 将单一 `src/app.js` 拆分为合理模块：渲染、输入/摄像头、触发、标定、音频、配置、UI。
- 使用清晰的类型契约；可采用原生 ES Modules + JSDoc，或引入 TypeScript 和轻量构建流程，但必须保持一键离线运行。
- 为 homography、触发滞回、坐标映射、配置校验编写单元测试。
- 浏览器 E2E 测试不得硬编码 Linux Chromium 路径，应使用 Playwright 管理的浏览器或可配置路径。
- E2E 至少覆盖：自动演示、指针、多点触摸、全乐队、响应式尺寸、标定有效/无效输入、摄像头拒绝权限、摄像头模拟输入、断线恢复、无外部请求、无控制台错误。
- 测试不得只检查“元素存在”；应验证行为和状态变化。

## 独立验收门槛

Codex 将至少执行以下验收；任一 P0 项失败即退回修改：

1. 语法、单元测试和 E2E 全部通过。
2. 63 个触发单元或经设计说明确认的等价非均匀触发区完整、无重叠、无空洞。
3. 1920×1080 和 1920×1200 下作品填满舞台，无大面积黑边。
4. 390×844 下可操作，核心内容可见，控制面板不溢出。
5. 指针和模拟摄像头人物只触发局部区域，不能误触全部画格。
6. 有效 homography 映射误差在离散测试点上可验证；无效四角配置被拒绝。
7. 摄像头拒绝、断线与重新连接不会导致页面崩溃。
8. 运行时外部网络请求为 0，控制台 error 为 0。
9. 连续压力运行测试期间无持续内存增长、音频漂移或 FPS 崩溃。
10. README、运行说明、资产许可说明和测试报告与实际实现一致。
